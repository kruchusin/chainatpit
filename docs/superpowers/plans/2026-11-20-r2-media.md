# ย้ายที่เก็บรูปไป Cloudflare R2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** แทน Firebase Storage ด้วย Cloudflare R2 สำหรับรูปทั้งหมด โดยอัปโหลดผ่าน Pages Function ที่ตรวจสิทธิ์ และแสดงผ่าน `/media/...` บนโดเมนเดียวกัน

**Architecture:** `functions/_lib/media-auth.js` (pure) ตัดสินสิทธิ์จาก path + ผู้ใช้ + เอกสารเป้าหมาย; `functions/api/media.js` (POST/DELETE) ใช้ `authenticate()` จาก `google-auth.js` อ่าน Firestore ด้วย service account แล้วเขียน/ลบใน `env.MEDIA`; `functions/media/[[path]].js` (GET) อ่านจาก R2. ฝั่ง client `uploadImage(path,file)` คง interface เดิมแต่เรียก `/api/media`.

**Tech Stack:** Cloudflare Pages Functions + R2 binding (`MEDIA`), Web APIs เท่านั้นใน functions; client ES modules; สคริปต์ย้ายข้อมูลใช้ `@aws-sdk/client-s3` (devDependency)

**Spec:** `docs/superpowers/specs/2026-11-20-r2-media-design.md` (แก้ไขเพิ่มจาก `docs/superpowers/specs/2026-11-19-school-website-design.md`)

## Global Constraints
- R2 bucket `chainatpit-media`, binding ชื่อ `MEDIA`
- path ที่อนุญาต: `news/{newsId}/{file}`, `staff/{staffId}/photo.jpg`, `departments/{deptId}/{file}`, `site/{file}`; id ตรง `^[A-Za-z0-9_-]{1,128}$`, file ตรง `^[A-Za-z0-9._-]{1,100}$` และห้ามเป็น `.`/`..`
- รับเฉพาะ `image/jpeg|image/png|image/webp|image/gif`, ขนาด ≤ 2*1024*1024 bytes
- URL ที่เก็บใน Firestore: `/media/<path>?v=<timestamp ms>` (relative)
- GET: `Cache-Control: public, max-age=31536000, immutable`; ไม่พบ → 404
- error ใช้ `errorJson(status, code, messageTh)` เดิม: 401 UNAUTHENTICATED "กรุณาเข้าสู่ระบบ", 403 FORBIDDEN "ไม่มีสิทธิ์ใช้งานส่วนนี้", 400 INVALID_INPUT "ข้อมูลไม่ถูกต้อง", 413 TOO_LARGE "ไฟล์รูปใหญ่เกินไป", 415 UNSUPPORTED_TYPE "รองรับเฉพาะไฟล์รูป JPG, PNG, WebP หรือ GIF", 500 INTERNAL "เกิดข้อผิดพลาดในระบบ กรุณาลองใหม่"
- functions ห้าม import npm; public/ ห้าม import npm
- Firebase ใช้แผน Spark ได้: ห้ามมี Firebase Storage เหลือใน client, rules, firebase.json, emulator config

## Review Focus
1. **ลบข่าวแล้วลบรูป:** เอกสารข่าวยังอยู่ตอนลบรูป (client ลบรูปก่อน) แต่ถ้าเอกสารหายไปแล้ว admin/pr_central ยังลบ prefix ได้ — Task 1 `delete news prefix without doc: central allowed, PR denied`
2. **path traversal / ชื่อไฟล์แปลก** (`news/x/../site/logo.jpg`, `%2F`, ไฟล์ว่าง) → 400 ไม่เขียนอะไร — Task 1 `rejects traversal and bad names`
3. **บัญชีถูกปิดแต่ token ยังไม่หมดอายุ** → 403 — Task 1 `disabled user denied`
4. **รูปปกข่าวแบบ relative ตอนแชร์ Facebook** → og:image เป็น absolute ด้วย origin ของ request — Task 3 `og: relative coverUrl made absolute`
5. **อัปโหลดไฟล์ใหญ่หรือไม่ใช่รูปแม้ client ย่อแล้ว (เรียก API ตรง)** → 413/415 และไม่เขียน R2 — Task 2 `POST too large → 413`, `POST svg → 415`
